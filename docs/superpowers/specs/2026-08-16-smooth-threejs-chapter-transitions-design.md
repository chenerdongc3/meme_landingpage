# Me 丝滑章节切换 — 设计说明

日期：2026-08-16  
状态：已确认，待规格复核

## 目标

- 保留 P1、P2、P3、P4、P7、P8 的全部正文与对应 Three.js 演出。
- 删除页面中所有类似 `P1 · 开场`、`P2 · 立场`、`P8 · 收尾` 的章节提示小字。
- 消除章节边界处 Three.js 整机横向位置瞬间跳变的问题，让正向滚动、反向滚动和直接跳转进度都呈现连续、可复现的过渡。

## 根因

`me-scene.js` 当前根据离散的 `state.chapter` 直接给产品根节点指定固定 `x` 坐标。章节一旦变化，根节点会在同一帧从上一章节位置跳到下一章节位置，造成闪现。零件开合虽然由连续进度驱动，但整机位姿没有连续时间线。

## 方案

以 `story-timeline.js` 作为唯一叙事状态源，为每个章节设置整机位姿关键帧，并按全局滚动进度连续插值，输出：

- `sceneX`：左右构图移动；
- `sceneY`：小幅上下漂移；
- `sceneZ`：轻微前后推拉；
- `sceneYaw`：轻微 Y 轴转向。

章节中心保持当前左右交错的构图意图；在章节交界前后使用 smoothstep 插值，整机沿连续轨迹进入下一构图，不再依赖离散章节判断。`me-scene.js` 只消费这些位姿值；`me-product.js` 继续负责零件开合、打印、拒绝、归档和撕纸动作。

移动端使用相同的连续状态，但缩小横向、纵向和景深位移，避免主体离开安全区域。`prefers-reduced-motion` 保留连续性，同时显著压低位移和转角幅度，不引入环境漂浮。

## DOM 调整

从六个章节中删除 `.chapter-index` 元素，不删除标题、正文、章节数据属性、进度轨、章节计数或无障碍状态。CSS 中不再需要的 `.chapter-index` 规则一并清理。

## 数据流

1. 滚动控制器计算归一化进度。
2. `deriveStoryState(progress)` 计算章节状态、零件动画参数和连续整机位姿。
3. DOM 控制器更新正文显隐与进度。
4. Three.js 场景使用连续位姿更新产品根节点和相机，不保存章节切换历史。

这种实现保证相同进度始终得到相同画面，快速滚动、反向滚动和测试脚本直接调用 `renderAt()` 时结果一致。

## 验证

- 结构测试确认所有 `.chapter-index` 提示文字均不存在，正文和六个章节仍然存在。
- 时间线测试确认位姿字段始终为有限值，并在每个章节边界前后保持连续，没有离散跳变。
- 产品与语法测试继续通过。
- 桌面、移动端及减少动态模式重新截图，人工检查章节切换附近主体没有闪现、越界或明显构图断裂。

## 非目标

- 不删除或改写任何章节正文。
- 不改变 P3、P4、P7、P8 的零件叙事含义。
- 不增加新的 UI 组件、后端接口或依赖。
